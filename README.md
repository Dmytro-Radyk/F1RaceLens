# F1 Race Lens

Вебзастосунок для фанатів Формули-1: результати сезону, профілі пілотів, порівняння виступів і зрозуміла аналітика для підготовки до Гран-прі.

Репозиторій: [Dmytro-Radyk/F1RaceLens](https://github.com/Dmytro-Radyk/F1RaceLens). Основна гілка — `master`.

## Поточний стан

Головна `/home` відкривається за замовчуванням і показує найближчий непідтверджений Гран-прі, розклад сесій, підтверджений прогрес сезону та топ-5 пілотів і команд. Календар і заліки завантажуються незалежно. [Поведінка та перевірки](context/features/home-overview.md).

Реалізовано календар поточного та минулих сезонів від 1950 року з реальними даними Jolpica, фільтри минулих і майбутніх етапів та сторінку Гран-прі з розкладом сесій. Вибраний рік зберігається в посиланні, наприклад `/calendar?season=2025`. Для старих етапів джерело може містити лише дату гонки. Календар доступний без входу. Інтерфейс адаптивний, має темну й світлу теми зі збереженням вибору.

На сторінці Гран-прі доступні вкладки розкладу, результатів гонки та кваліфікації; спринт — для відповідних вікендів. Результати завантажуються при відкритті вкладки, підтримують історичні сезони, кеш і повторну спробу після помилки. Приклад: `/calendar/2025/1?session=race`. Деталі — у [контракті результатів](context/architecture/results-api.md).

У розділі `/standings` доступні заліки пілотів і команд з очками та перемогами. Поточний сезон показує останній доступний залік із номером етапу; минулі — підсумки джерела. Вибраний рік зберігається між календарем і таблицями, наприклад `/standings?season=2025&table=constructors`. Історичні трансфери, дробові очки та дискваліфікації підтримуються; [контракт заліків](context/architecture/standings-api.md).

У розділі `/drivers` можна вибрати пілота зі заліку сезону. Профіль `/drivers/norris?season=2025` містить довідкові дані, очки й перемоги чемпіонату, результати гонок та доступний графік старту й фактичного фінішу. Профілі відкриваються також із таблиць результатів і заліку. Сходи, пропуски й неоднозначні історичні результати не перетворюються на вигадані точки графіка. Деталі — у [контракті профілю](context/architecture/driver-profile-api.md).

Розділ `/teams?season=2025` показує команди зі заліку конструкторів. Профіль `/teams/mclaren?season=2025` містить місце, очки, перемоги й пілотів за сезон із переходами до їхніх профілів. Очки пілота за весь сезон не приписуються команді. У 1950–1957 показуються конструктори — учасники гонок і їхні пілоти, без неіснуючого командного заліку. Деталі — у [описі команд](context/features/season-teams.md).

У розділі `/compare?season=2025&first=norris&second=piastri` доступне порівняння гонок двох пілотів: офіційні показники заліку, фактичні фініші, очний рахунок, спільний графік і таблиця. Сходи та неоднозначні історичні записи не ранжуються як фініші. [Правила порівняння](context/features/driver-comparison.md).

Розділ `/insights?season=2025&driver=norris&window=5` аналізує останні 5 або 10 етапів участі пілота: фактичні фініші, зміну позиції, попередній відрізок та короткі висновки з явними розмірами вибірок. [Правила аналітики](context/features/driver-analytics.md).

Вкладка `/predictions` містить експериментальний прогноз майбутніх Гран-прі та підсумкових заліків актуального сезону: 4 000 симуляцій, частки титулу/топ-3 та діапазони очок і місць. Очікувані очки відображаються цілими числами; минулі етапи не прогнозуються повторно. Тут працює статистичний скрипт, окремий від LightGBM. Частоти ще не відкалібровані; історичні перевірки збережені в документації. [Контракт, модель та перевірка](context/features/season-predictions.md).

API поки зберігає дані лише в кеші пам’яті. Окремий ML-експеримент зберігає сирі дані, ваги й зафіксовані прогнози у файлах `ml/` на диску, виключених із Git. PostgreSQL ще не підключено. Підготовлено [план сутностей PostgreSQL](context/architecture/data-storage-plan.md), який враховує трансфери, кілька результатів одного етапу, сирі імпорти й авторитетні знімки заліку.

На сторінці `/login` вхід `admin` / `12345` є лише демонстраційною перевіркою у frontend. Реєстрація, зовнішня авторизація, відновлення пароля, порівняння кваліфікацій і спринтів, постійне сховище й персоналізація ще заплановані.

## Локальний запуск

Потрібні Git, стабільний .NET 10 SDK, Node.js 24.15.0 або новіша сумісна версія гілки 24.x і npm 11. Вимоги Node відповідають Angular-залежностям, зафіксованим у `frontend/package-lock.json`.

В одному терміналі з кореня репозиторію запустіть API:

```powershell
dotnet run --project backend/F1RaceLens.Api --launch-profile http
```

В іншому терміналі запустіть frontend:

```powershell
cd frontend
npm ci
npm run start
```

Після запуску відкрийте <http://localhost:4200/home>. API працює на <http://127.0.0.1:5080>; Angular development-проксі перенаправляє запити `/api/**` на цей порт.

Потрібен доступ сервера до `api.jolpi.ca`. Календар кешується в пам'яті; PostgreSQL для цього етапу не потрібний. Деталі контракту та кешування — в [описі API календаря](context/architecture/calendar-api.md).

## Перевірки

З кореня репозиторію:

```powershell
dotnet build backend/F1RaceLens.slnx
dotnet test backend/F1RaceLens.slnx
```

З директорії `frontend`:

```powershell
npm run build
npm test -- --watch=false
```

## Структура

- `frontend/` — клієнтський застосунок Angular.
- `backend/` — ASP.NET Core API, статистичні прогнози, тести й консольна перевірка прогнозів.
- `ml/` — окреме навчання LightGBM, симуляції, журнал прогнозів і локальний перегляд на порту 4300.
- `context/` — опис продукту, поточна задача, правила роботи й дизайн-референси.
- `.agents/skills/` — проєктні навички для роботи з AI.
- `AGENTS.md` — початкові інструкції для AI-агента.

## Подальша розробка

Перед початком задачі оновлюємо `context/current-feature.md`, створюємо окрему гілку `feature/...`, `fix/...` або `chore/...`, реалізовуємо зміни й перевіряємо їх. Коміт робимо лише за окремою командою користувача після успішної збірки та потрібних перевірок. Злиття в `master` і публікацію в GitHub погоджуємо окремо від локального коміту.

Детальний процес описаний у [правилах взаємодії з AI](context/ai-interaction.md), продукт — в [огляді проєкту](context/project-overview.md).

Локальні секрети, залежності, результати збірки й персональні налаштування Codex виключені через `.gitignore`.


Прогнози v2 враховують статистику трас за два попередні сезони, поточну команду пілота й доступну погоду Open-Meteo. На сторінці можна задати тимчасовий сценарій дощу, поступової зміни темпу команди та заміни пілота з майбутнього етапу. Невідомі погода, оновлення й заміни не вигадуються; показники залишаються експериментальними.

Окремий [локальний експеримент LightGBM](ml/README.md) навчає порядок пілотів і ризик некласифікації на історичних результатах. Моделі й середовище розміщені на E: та виключені з Git. Поточні прогнози застосунку залишаються на статистичному симуляторі до окремої інтеграції та перевірки.

Для окремого ML-перегляду потрібні Python 3.13 та uv: інструкція встановлення й навчання — у [ML README](ml/README.md). Файли ваг не постачаються з репозиторієм. LightGBM v1–v4 дають передвікендний прогноз, q1 — уточнення після кваліфікації за наявності даних. [Знімки до старту та оцінювання](context/features/post-qualifying-forecasts.md), [індекс перевірок](context/validation/README.md). Вкладки вибору скрипта/ML у застосунку, чат-бот із RAG та БД залишаються наступними задачами.
