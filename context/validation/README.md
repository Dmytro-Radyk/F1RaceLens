# Перевірки прогнозів

Це збережені звіти на момент експериментів, а не актуальний прогноз або автоматично оновлювана панель. Команди відтворення — у [ML README](../../ml/README.md) та [контракті скрипта](../features/season-predictions.md).

| Група файлів | Значення |
| --- | --- |
| [integrated-forecasts.md](integrated-forecasts.md) | Інтеграція двох рушіїв, PostgreSQL-журнал, ревізії оцінок і перевірки UI/API |
| `prediction-backtest*.json` | Історична перевірка статистичного C#-скрипта на зрізах сезону 2025 |
| `lightgbm-audit-2025.json`, `lightgbm-v1.json` | Початковий LightGBM: аудит 2025 та послідовний аудит 2026 |
| `lightgbm-v2/v3/v4-*` | Вибір параметрів, порівняння й аудит кожної версії; окремі файли зберігають результат експерименту |
| `qualifying-q1-*.json` | Модель із кваліфікацією; порівнювати з простим порядком кваліфікації, а не лише з прогнозом до вікенду |
| `prospective-initial-2026-10-19.json` | Початковий стан журналу: 6 очікуваних прогнозів, 0 оцінених гонок |
| `catboost-*`, `external-usgp-2026.*` | Архів вилученого рушія та його зовнішнього порівняння; не описує активний LightGBM |

MAE залежить від задачі: місця гонки та місця підсумкового заліку не можна прямо зіставляти. Brier ризику некласифікації в ML-аудитах — бінарна метрика; multiclass Brier переможця в журналі — інша метрика. Влучення фаворита також не доводить калібрування всіх відсотків.

Роки 2025/2026 уже використовувалися під час розробки, тому ретроспективні результати не є свіжим незалежним тестом. Зовнішні прогнози не використовувалися для підбору LightGBM. [Правила фіксації та оцінювання](../features/post-qualifying-forecasts.md) описують майбутню перевірку: оцінку можна оновити після виправлення результату, зафіксований прогноз не перезаписується. Ваги, сирі дані та робочий журнал виключені з Git; тут зберігаються лише підсумки перевірок.
