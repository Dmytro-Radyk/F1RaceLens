# Календар: контракт і джерело даних

## Поточна реалізація

Angular → `/api` через проксі → ASP.NET Core .NET 10 → Jolpica. Календар і розклад доступні гостям. Демо-вхід зберігається для перевірки майбутніх персональних розділів.

Сервер використовує `IHttpClientFactory`, ідентифікує себе як `F1RaceLens/0.1.0` і має таймаут 12 секунд. Зовнішній URL зафіксований у конфігурації клієнта, не береться з користувацьких параметрів.

Джерело: [Jolpica](https://github.com/jolpica/jolpica-f1/blob/main/docs/README.md). Календар: `https://api.jolpi.ca/ergast/f1/current.json?limit=100`. Поточний сезон визначає провайдер, а не жорстко заданий рік у frontend. Якщо відповідь обрізана або має некоректні основні поля, API повертає контрольовану помилку.

## Маршрути

| Запит | Відповідь |
| --- | --- |
| `GET /health` | Стан процесу API |
| `GET /api/seasons/current/calendar` | Календар поточного сезону |
| `GET /api/seasons/{season}/calendar` | Календар вибраного року |
| `GET /api/seasons/{season}/races/{round}` | Розклад конкретного етапу |

Дозволені роки: від 1950 до наступного календарного року включно. Номер етапу — від 1 до 100. Некоректні параметри повертають `400`, відсутній етап — `404`, недоступне джерело без придатного кешу — `503` з `Retry-After: 60`. Помилки оформлені як Problem Details.

Frontend пропонує роки від 1950 до поточного календарного року UTC. `/calendar` завантажує `current`, `/calendar?season=2025` — конкретний рік. Вибір року змінює URL, підтримує історію браузера та скидає фільтр етапів. Посилання зі сторінки Гран-прі повертає до відповідного сезону. Сезони завантажуються окремо за потреби через наявний API і кеш; масового імпорту архіву немає. Некоректний рік у URL показує помилку без запиту до API.

## DTO

Календар: `season`, `updatedAt`, `isStale`, `source`, `races`.

Етап: ті самі метадані та `race` замість `races`.

Кожен етап містить `season`, `round`, `name`, `circuit`, `date`, `startsAt`, `sessions`. Траса: `id`, `name`, `locality`, `country`. Сесія: `kind`, `name`, `date`, `startsAt`.

`date` — дата у форматі `yyyy-MM-dd`. `startsAt` — ISO 8601 з UTC-зсувом або `null`, якщо час невідомий. Сесії повертаються лише за наявності даних, плюс гонка; спринтерський вікенд не доповнюється вигаданими практиками. Frontend переводить відомий час у часовий пояс браузера, а дату без часу показує без UTC-зсуву дня.

## Кеш і актуальність

- Свіжий знімок зберігається в пам'яті сервера 15 хвилин; запити `current` і відповідного року використовують спільні дані.
- Одночасні запити не спричиняють повторний імпорт тієї самої відповіді.
- Якщо джерело недоступне, знімок віком до 24 годин повертається з `isStale: true`. Початковий `updatedAt` не змінюється; frontend показує попередження.
- Після помилки повторна спроба до джерела відбувається не раніше ніж через хвилину. Це не продовжує 24-годинний строк зберігання знімка.
- Після перезапуску сервера кеш порожній. Постійного сховища PostgreSQL і фонового імпорту в цій задачі немає.

Мітки «Минулі» й «Майбутні» визначаються за розкладом. Календар не містить офіційного результату гонки чи окремого надійного статусу скасування; ці дані не вигадуються.

## Запуск і розгортання

API: `dotnet run --project backend/F1RaceLens.Api --launch-profile http` — `http://127.0.0.1:5080`.

Frontend: `npm run start` із `frontend`. `frontend/proxy.conf.json` спрямовує `/api/**` на порт 5080. Обидва процеси мають працювати одночасно.

Для production потрібно налаштувати HTTPS і reverse proxy: `/api` до ASP.NET Core, інші маршрути — до Angular із fallback на `index.html`. Development-проксі не входить у production-збірку.
