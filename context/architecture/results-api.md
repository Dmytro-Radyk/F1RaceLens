# Результати: контракт API

`GET /api/seasons/{season}/races/{round}/results/{kind}` доступний без входу.

`season`: чотири цифри, 1950–наступний календарний рік UTC; `round`: 1–100; `kind`: `race`, `qualifying`, `sprint`. Некоректні параметри — `400`, відсутній у календарі етап — `404`, недоступне або некоректне джерело без придатного кешу — `503` Problem Details з `Retry-After: 60`. Порожні результати — `200` з `entries: []`, не `404`.

## Дані

Відповідь: `season`, `round`, `kind`, `updatedAt`, `isStale`, `source`, `entries`.

Рядок `entries`: `position` (число), `positionText`, `driverId`, `driverName`, `driverCode`, `team`, `grid`, `laps`, `time`, `status`, `points`, `q1`, `q2`, `q3`. Відсутні поля — `null`; порожні рядки нормалізуються до `null`. `points` — десяткове число, включно з дробовими історичними очками. `time` — форматований рядок джерела (повний час або відставання), не дата і не локальний час. Значення Q1/Q2/Q3 не перераховуються й не доповнюються.

Рядки впорядковані за числовим `position`; `positionText` зберігає класифікацію джерела. Не припускаємо унікальності пілота чи позиції для історичних спільних автомобілів. Нульова стартова позиція не перетворюється безумовно на піт-лейн.

## Джерело та кеш

Клієнт використовує спільний `IHttpClientFactory` Jolpica із зафіксованим HTTPS-хостом, таймаутом 12 секунд, User-Agent та `CancellationToken`.

- [Гонка](https://github.com/jolpica/jolpica-f1/blob/main/docs/endpoints/results.md): `{season}/{round}/results.json?limit=100`.
- [Кваліфікація](https://github.com/jolpica/jolpica-f1/blob/main/docs/endpoints/qualifying.md): `{season}/{round}/qualifying.json?limit=100`.
- [Спринт](https://github.com/jolpica/jolpica-f1/blob/main/docs/endpoints/sprint.md): `{season}/{round}/sprint.json?limit=100`.

Адаптер перевіряє сезон, етап, основні поля, кількість рядків проти `total`; обрізана відповідь не стає неповною таблицею. Помилки джерела не видаються за порожні результати.

Ключ кешу — сезон/етап/сесія. Непорожні дані свіжі 15 хвилин, порожні — одну хвилину, щоб нові результати швидше з’являлися. При помилці збережені дані віком до 24 годин повертаються з `isStale: true`; час початкового оновлення зберігається, повторна спроба — через хвилину. Це не продовжує строк зберігання. Конкурентні запити до кешу об’єднуються. Кеш у пам’яті очищається при перезапуску; бази даних і фонового імпорту немає.

Frontend використовує окремі метадані результатів; час оновлення календаря не підміняє час оновлення таблиці. Відсутня історична сесія й майбутній результат мають різні пояснення; жодне з них не є офіційним статусом скасування.
