# PostgreSQL: перший етап постійного зберігання

## Реалізовано

PostgreSQL 18.6, EF Core 10.0.4 та Npgsql EF provider 10.0.3. Джерела походження: [офіційні Windows-дистрибутиви PostgreSQL](https://www.postgresql.org/download/windows/), [архів EDB](https://www.enterprisedb.com/download-postgresql-binaries), [Npgsql EF 10](https://www.npgsql.org/efcore/release-notes/10.0.html). Нових frontend- або ML-залежностей немає.

На цьому ПК runtime і кластер — `E:/F1RaceLensDatabase/runtime` та `E:/F1RaceLensDatabase/data`. Шлях має бути ASCII через обмеження Windows-ініціалізації PostgreSQL. Порт 55432, слухає лише 127.0.0.1, автентифікація SCRAM-SHA-256. Прикладний користувач не є суперкористувачем і не може створювати ролі чи БД. Це локальний процес; автоматичний старт разом із Windows не налаштований.

У `.local/database-path.json` — шлях установки. Паролі генеруються випадково, зберігаються лише у приватних локальних файлах `.local/admin-password` і `backend/F1RaceLens.Api/appsettings.Local.json`, виключених із Git. ACL обмежено поточним Windows-користувачем і SYSTEM. Не публікувати ці файли, дампи й каталог кластера.

## Схема та читання

Міграції — `backend/F1RaceLens.Api/Storage/Migrations/`. Таблиці: `Seasons`, `Drivers`, `Constructors`, `Circuits`, `Races`, `Sessions`, `Results`, `Standings`, `Participations`, `Documents`, `Snapshots`, `ImportPages`. Є зовнішні ключі, індекси пошуку та ключі ідемпотентності. `DateOnly` відображається у date; часові мітки — timestamptz UTC; очки — numeric без штучного обмеження дробової точності, зі знаком.

`Snapshots` зберігає повний нормалізований DTO ресурсу з вихідним часом, роком, хешем, часом наступного оновлення. GET календаря, Гран-прі, результатів, заліків, профілів пілотів та історичних учасників спочатку читає останній зріз БД. `current` відповідає ключу поточного UTC-року; чужий рік не видається під новим alias. Формат і маршрути публічних DTO не змінено.

Коли свіжого зрізу немає, працюють наявні адаптери й їхній короткий кеш. Тільки успішний повний результат адаптера публікується транзакційно разом із захопленими сторінками джерела й проєкціями. Паралельні публікації серіалізуються advisory-lock; повторний хеш відповіді не створює дублів. Публікація відбувається на рівні ресурсу, не всього сезону разом: перерваний CLI-імпорт можна повторити. Застаріла відповідь не публікується як нова. Помилка БД повертає 503; прихованого переходу на непостійний кеш немає. Без рядка підключення запуск зупиняється; `Storage__Required=false` дозволяє явний діагностичний режим без БД.

Звичайний зріз оновлюється через 15 хвилин від `updatedAt`, порожній — через хвилину. При 503 джерела можна видати історичний збережений ресурс із `isStale=true` без зміни часу; для актуального/майбутнього сезону зберігається обмеження 24 години. Самі записи БД не видаляються через закінчення цього часу. 400/404, часткові/невалідні завантаження та відхилені імпорти не замінюють попередній зріз.

`Documents` містить незмінний сирий текст JSON, URL, SHA-256 і версію адаптера; текстовий тип зберігає байтове UTF-8 представлення, яке JSONB нормалізував би. `ImportPages` пов’язує ресурс із джерелами й часом отримання. При використанні вже валідованого кешу сервісу нових зовнішніх сторінок може не бути.

Нормалізовані довідники й проєкції формуються із сирих документів, а публічні читання зараз використовують готові DTO-зрізи. Це свідомий перший етап: довільні SQL-звіти не повинні змішувати старі версії документів. Для актуального набору результатів/заліків потрібно обирати останній ресурс і його маніфест `ImportPages`. `Results` і `Standings` мають ключ документ+порядковий запис; пара пілот+сесія не унікальна. Переходи — множинні участі сезон+пілот+конструктор. Історичні імена, деталі часу, Q1/Q2/Q3 та сирі номери машин лишаються також у payload документа/рядка. Офіційні заліки не виводяться простим підсумовуванням гонок.

## Команди PowerShell 7 з кореня

```powershell
./scripts/database/Setup.ps1
./scripts/database/Start.ps1
dotnet run --project backend/F1RaceLens.Api --launch-profile http
# Інший термінал після запуску API:
./scripts/database/Import-Season.ps1 -Season 2026 -IncludeProfiles
./scripts/database/Import-Season.ps1 -Season 1953
./scripts/database/Backup.ps1
# Відновлення тільки у НОВУ окрему БД, основна не перезаписується:
./scripts/database/Restore.ps1 -BackupFile '<backup.dump>' -TargetDatabase f1racelens_restore_inspection
# Після зупинки API, коли БД більше не потрібна:
./scripts/database/Stop.ps1
```

Setup відмовляється перезаписувати сторонню установку/кластер або локальний конфіг; на налаштованій установці запускає PostgreSQL і застосовує міграції. Для іншого хоста PostgreSQL задайте `ConnectionStrings__RaceLens` через захищене середовище; локальні скрипти призначені лише для loopback. Для нових міграцій локально встановити `dotnet-ef` 10.0.4, потім `dotnet ef migrations add <Name> --project backend/F1RaceLens.Api --output-dir Storage/Migrations`; застосування — `dotnet run --project backend/F1RaceLens.Api --no-launch-profile -- --migrate`. Міграції не запускаються неявно кожним HTTP-процесом.

Імпортер працює послідовно, з паузами, обмеженими повторами та перевіркою `/health/storage`. Для поточного сезону бере лише підтверджені етапи зі заліку. Всі історичні сезони не завантажуються автоматично: вони імпортуються за запитом через UI або явною командою. Дампи — `.local/backups/`; зберігайте окрему захищену копію поза цим комп’ютером, якщо дані стають робочими.

## Перевірки 19.10.2026

90 backend-тестів успішні, включно з трьома сценаріями на справжній PostgreSQL у тимчасових ізольованих схемах. Без `RACELENS_TEST_DATABASE` ці три сценарії явно позначені skipped. Щоб виконати їх локально, тимчасово задайте цю змінну рядком підключення тестової БД; не друкуйте секрет у логах. Перевірено конкурентний повторний імпорт, дробові/від’ємні очки, кілька записів пілота, raw JSON, повний rollback, читання без виклику джерела та stale-політику.

Реально імпортовано 2026 (17 підтверджених етапів і профілі) та 1953 (9 етапів і конструктори). На контрольному зрізі: 135 ресурсних знімків, 1495 рядків результатів, 133 сирі сторінки; 14 груп мають кілька записів пілота в одній сесії й не були злиті. Перезапуск PostgreSQL і відновлення дампа в окрему нову БД пройшли, контрольні кількості збіглися.

## Графічний перегляд локальної БД

На цьому ПК встановлено pgAdmin 4 9.18 з [офіційного дистрибутива](https://www.pgadmin.org/download/pgadmin-4-windows/): `E:/pgAdmin4/runtime/pgAdmin4.exe`. Профіль клієнта — `E:/F1RaceLensDatabase/pgadmin-profile`; підключення **Local databases → F1 Race Lens** зареєстровано для локальної `f1racelens` на порту 55432. Приватний password file у захищеній директорії профілю дозволяє підключатися без ручного введення пароля; його не копіювати в Git або повідомлення.

У дереві відкрити **Databases → f1racelens → Schemas → public → Tables**. Для рядків таблиці: права кнопка → **View/Edit Data → First 100 Rows**. Основні таблиці: `Results`, `Races`, `Drivers`, `Constructors`, `Standings`; `Documents` та `Snapshots` містять джерела й опубліковані зрізи. PostgreSQL має бути запущена через `scripts/database/Start.ps1`; запуск клієнта сам по собі не запускає сервер.

Перевірено підключення через Python/psycopg, що постачається з pgAdmin, з тим самим password file: прочитано 1495 рядків `Results`. Інсталятор перевірено за SHA-256 та цифровим підписом.

## Наступні етапи

Додано наступну міграцію журналу: ForecastRuns, ForecastSeals, ForecastScores. [Інтегровані прогнози](../features/integrated-forecasts.md). C#-скрипт продовжує отримувати входи через свої адаптери, але зберігає точний зріз у журналі. Ваги LightGBM залишаються файлами. Справжня авторизація, платежі, RAG, розклад імпорту, політика зберігання версій, окремий migration-role та автоматизовані позамашинні резервні копії — наступні задачі.
