# Зміна та відновлення пароля

У `/profile` є форма поточного, нового та повторного нового пароля. Новий пароль — 12–128 символів, пробіли зберігаються; він має відрізнятися від поточного. Сервер перевіряє поточний пароль через Identity з lockout (5 помилок / 10 хвилин), CSRF та спільним обмеженням account-entry (20 запитів / хвилину / IP). Зміна не приймає ID користувача: акаунт визначається тільки з principal. Identity оновлює security stamp, поточна cookie перевидається. Stamp перевіряється на кожному автентифікованому запиті: інші сесії втрачають доступ на наступному запиті. Це додає читання Identity з БД, без окремого реєстру пристроїв.

## Відновлення

- `/forgot-password`: пошта, `POST /api/auth/forgot-password {email}`. Після черги 202 з однаковим порожнім тілом для відомої та невідомої адреси. Пошук акаунта і доставка відбуваються після відповіді у worker, щоб не розкривати існування через час SMTP. 5 запитів / 15 хвилин / IP; CSRF обов’язковий навіть для гостя.
- Identity Data Protection створює захищений токен на **30 хвилин**, прив’язаний до користувача та security stamp. Зміна/відновлення пароля робить попередні токени недійсними. Успішно використати один токен повторно не можна.
- Посилання має вигляд `/reset-password#user=…&token=…`: секрет у fragment, а не в query/access logs/referrer. Форма читає його в оперативну пам’ять і прибирає fragment з поточної адреси через replaceState; браузер або поштовий сервіс усе одно може зберігати саме початкове посилання. Токен передається API тільки в тілі POST і не потрапляє до localStorage. Паролі очищаються після запиту.
- `POST /api/auth/reset-password {userId, token, newPassword}`: без входу, з CSRF і account-entry limiter. Помилка невідомого ID/неправильного/простроченого токена однакова. Після успіху сервер завершує cookie поточного браузера, інші сесії відкликає stamp. Автоматичного входу немає. Тимчасове блокування за невдалі входи не скасовується reset-запитом.
- Вебформи, повідомлення й транзакційні листи підтримують шість мов. [Підтвердження та зміна пошти](account-email-personal-home.md) додані наступним етапом. MFA та керування окремими пристроями ще не реалізовані.

## SMTP — окреме налаштування

**Локально налаштовано Gmail SMTP.** Користувач сам зберіг пароль застосунку локальним скриптом і показав прийняття тестового листа Gmail. [Налаштування та межі](account-email-personal-home.md). Без SMTP запит однаково повертає 503 `recovery-unavailable` для будь-якої адреси; UI не імітує доставку. Зміна пароля у профілі працює незалежно від SMTP. Автоматичні тести ніколи не використовують справжню поштову доставку.

Налаштування задаються у виключеному з Git `backend/F1RaceLens.Api/appsettings.Local.json`, user secrets або змінних середовища; існуючі приватні налаштування БД не перезаписувати:

| Ключ | Значення |
| --- | --- |
| `PasswordRecovery:PublicOrigin` | Фіксований HTTPS origin; у Development також HTTP loopback. Без шляху, query, fragment, credentials; не береться з Host запиту |
| `PasswordRecovery:SmtpHost` | Довірений SMTP-сервер |
| `PasswordRecovery:SmtpPort` | Порт STARTTLS, типово 587; implicit TLS 465 не підтримується SmtpClient |
| `PasswordRecovery:From` | Дозволена сервісом адреса відправника |
| `PasswordRecovery:Username` | SMTP-логін |
| `PasswordRecovery:Password` | Секрет SMTP/app password |

Для env використовуються `PasswordRecovery__PublicOrigin` тощо. Перезапустити API після налаштування. TLS обов’язковий, перевірка сертифіката не вимикається; строк одного надсилання — 15 секунд. Використовується вбудований .NET SMTP-клієнт, нових пакетів/платних сервісів не додано. Не логувати SMTP-винятки, тіла, адреси, токени, паролі чи cookie.

Черга в оперативній пам’яті обмежена 64 запитами; переповнення дає однаковий 503. Черга не переживає перезапуск, автоматичних повторів немає. Помилки доставки дають лише загальний warning; 202 означає прийняття, а не підтверджену доставку. Для production потрібні перевірений SMTP, HTTPS, довірений proxy, моніторинг доставки та за потреби стійка приватна outbox-черга й спільні rate limits для кількох інстансів. Платність залежить від вибраного SMTP-провайдера; підписку не оформлено.

## Перевірки

Ізольовані PostgreSQL/HTTP-тести перевіряють старий/новий пароль, поточну та іншу сесії, прив’язку токена до користувача, повторне використання, закінчення строку, скасування токена зміною пароля, CSRF, однакові відповіді без SMTP й обмеження спроб. Frontend-тести перевіряють розбіжність паролів, очищення полів, token тільки в POST, чесний 503 та axe структуру форми. Немає міграції чи змін реальних користувацьких паролів.

Початкова перевірка: 131 backend і 139 frontend-тестів, production build без попереджень, 897 повідомлень локалізації. Живі українська/німецька форми й ширина 320 px без горизонтального переповнення. Подальше налаштування Gmail і нові перевірки — у контракті пошти акаунта.
