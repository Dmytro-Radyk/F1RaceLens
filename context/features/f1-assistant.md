# Тимчасовий F1-асистент

Сторінка `/assistant` — локальний мовний співрозмовник із пошуком у публічних даних додатку та зовнішній Wikipedia; новини — із BBC Sport. Це окрема Qwen3-4B-Instruct-2507, а не LightGBM для прогнозів. Розмову можна почати без акаунта; з публічних сторінок є дія «Запитати асистента», яка передає лише маршрут і числовий сезон, без довільного пошукового тексту чи приватного профілю.

Інтерфейс займає доступну висоту сторінки: прокручується стрічка повідомлень, поле введення залишається внизу. Enter надсилає, Shift+Enter додає рядок; IME-композиція не надсилається. Автопрокручування не відбирає позицію в користувача, який читає старі повідомлення; є перехід до останнього. Доступні Stop, повторна спроба й нова розмова.

## Зовнішній пошук

Перемикач «Пошук у мережі» зберігається лише в RAM, у UI початково ввімкнений. Для HTTP-клієнтів прапорець `webSearch` початково false. `ExternalKnowledge` звертається до фіксованого [MediaWiki Action API](https://www.mediawiki.org/wiki/API:Search) однієї з шести Wikipedia. Для транслітерованих імен/латинських запитів використовується англійська Wikipedia; модель перекладає відповідь.

Назовні йдуть лише до восьми пошукових слів останнього запитання (або до шести розпізнаних відповідників імен), без попередніх реплік, маршруту й cookies акаунта. Пошук відкидає URL, email, довгі ідентифікатори й числа від п’яти цифр; це евристика, не універсальний DLP-фільтр — не вводьте секрети. Wikimedia отримує пошукові слова та мережеву адресу сервера; локальне незбереження не визначає політику зовнішнього провайдера. Немає журналювання вихідних пошукових URL в HttpClient.

Отримуються до трьох коротких вступних уривків (до 700 символів) із фільтром автоспортивної тематики, тайм-аутом 8 секунд і лімітом відповіді 128 KiB. Немає довільного завантаження адрес із повідомлення/моделі, cookies, редиректів чи виконання HTML. У разі збою чат використовує доступні локальні дані; статус пошуку показується окремо. «Знайдені вебсторінки» — результати пошуку, а не обов’язково процитовані чи повністю передані моделі сторінки. «Джерела відповіді» містять лише дозволені ID, які повернула модель. Дата отримання енциклопедичного уривка не означає дату актуальності факту. Це зовнішній пошук по Wikipedia та RSS BBC, а не універсальна пошукова система всього інтернету; платних ключів не потрібно.

## Життєвий цикл і приватність

Повідомлення й чернетка живуть лише в root Angular-сервісі в RAM конкретної вкладки. Внутрішня навігація зберігає бесіду. Нова розмова, `pagehide` (включно з переходом документа до back-forward cache), перезавантаження/закриття або зміна ідентичності акаунта очищають їх і скасовують HTTP-підписку. Пізній результат не застосовується завдяки номеру покоління запиту. BroadcastChannel передає тільки сигнал очищення між вкладками, без повідомлень чи ідентифікатора акаунта. Історія між вкладками не синхронізується.

Історія не пишеться в PostgreSQL, localStorage/sessionStorage, URL чи журнали. Backend не має серверного словника бесід: кожен запит містить лише поточний обмежений контекст. Runtime працює на loopback, без web UI, slot monitoring, журналів і повторного використання prompt cache. Тимчасові буфери запиту/відповіді та KV у RAM неминучі під час обчислення; це не обіцянка криптографічного стирання фізичної пам’яті. Зовнішній AI API не використовується. Не вмикати body tracing, дампи промптів чи запис відповідей у reverse proxy/телеметрії.

## Дані й відповіді

`AssistantKnowledge` виконує обмежений лексичний пошук (перша RAG-версія, без embeddings) по F1DB, збережених спортивних snapshot, стислих прогнозах із журналу, заголовках BBC Sport та невеликій редакційній довідці. Є нормалізація діакритики та початкові українські відповідники прізвищ. Підрахунки/SQL не генеруються моделлю; до Identity/обраного/пошти доступу немає.

Локальні знімки можуть бути старими або відсутніми. Асистент не імпортує сезони, не запускає навчання/прогнози й не видає відсутні значення за нуль. Список результатів може бути частковим — це позначається в evidence. Для кар’єри передається зріз F1DB за сезоном/етапом, для спортивних ресурсів і прогнозів — дата збереження/формування. Свіжість не гарантується фактом наявності рядка у БД.

Модель отримує інструкції відповідати вибраною мовою, відокремлювати оцінки від фактів, уточнювати неоднозначний сезон, не вигадувати статистику чи зміст статті за заголовком. Відповідь — JSON `{ answer, sourceIds }`; backend допускає лише ID переданих джерел. Текст у UI відображається як plain text, без HTML чи виконуваного Markdown. Посилання формує retrieval, не модель; frontend додатково перевіряє схему/домени. Наявність джерела не гарантує правильного тлумачення моделлю.

Коли мережевий пошук вимкнено, короткі запитання з ключовими словами undercut/overcut мають окрему редакційну довідкову відповідь шістьма мовами без запуску моделі. UI явно розрізняє «Довідка з джерела» (`kind: reference`) і «Відповідь мовної моделі» (`kind: model`). Це обмежений словниковий маршрут, а не семантична класифікація всіх намірів. Для решти запитань працює локальна мовна модель. Пошук враховує останні три запитання та конкретного пілота/команду з маршруту; загальний маршрут календаря не підміняє тему запиту. Новини й прогнози отримують пріоритет за відповідним наміром.

Універсального вебпошуку, повних текстів новин, live-таймінгу, векторного пошуку та гарантованого покриття всіх правил немає. Це прототип для коротких бесід, не перевірений універсальний F1-експерт. Якість української/інших мов і відповідей потребує ширшого набору прикладів та подальшої оцінки. Відповідь без релевантних джерел слід перевіряти особливо уважно.

## HTTP-контракт

- `GET /api/assistant/status` → `{ ready, model }`, перевірка локального `/health`, `Cache-Control: no-store`.
- `POST /api/assistant/chat` → `{ language, messages: [{ role, content }], page?, webSearch? }`; відповідь `{ answer, sources: [{ id, title, url, text: "" }], model, kind, webStatus, webSources }`.
- Мови: `uk/en/de/it/es/fr`; ролі тільки user/assistant, по черзі з user, останній user. До 12 повідомлень, 3000 символів на повідомлення, разом до 6000; публічний маршрут до 240 символів. UI приймає до 1500 символів і передає до 11 повідомлень/5000 символів. Старі повні пари вилучаються з контексту, не з видимої поточної бесіди. Перед генерацією локальний tokenizer точно перевіряє бюджет 1400 вхідних токенів; за потреби вилучаються найстаріші пари й нижчі за пріоритетом джерела. Залишено запас на обрамлення чату та до 384 вихідних токенів; коротка відповідь обмежена 1000 символами.
- Тіло до 64 KiB, до 8 запитів/хвилину з IP, одне обчислення моделі одночасно без черги, тайм-аут 150 секунд. Cross-site браузерні POST відхиляються. Cookies/профіль не передаються runtime.
- 400 — некоректний контекст, 413 — тіло завелике, 429 — обмеження/модель зайнята, 503 — runtime/дані/формат відповіді недоступні. Помилки не містять промптів чи повідомлень користувача.

## Локальне встановлення на Windows

Офіційні джерела: [Qwen3-4B-Instruct-2507 GGUF](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507-GGUF), [llama.cpp b11808](https://github.com/ggml-org/llama.cpp/releases/tag/b11808). Модель Qwen від Alibaba, квантована збірка Unsloth, runtime ggml-org; CatBoost та російські сервіси не додаються. Ваги й архіви завантажуються з фіксованих revision/release і перевіряються SHA-256. Перегляньте ліцензії відповідних upstream-проєктів перед розповсюдженням ваг/runtime.

```powershell
./scripts/assistant/Setup.ps1
./scripts/assistant/Start.ps1
# Для CPU без сумісного NVIDIA GPU (суттєво повільніше):
# ./scripts/assistant/Start.ps1 -Cpu
# Для видимого терміналу діагностики життєвого циклу, без промпт-логів:
# ./scripts/assistant/Start.ps1 -Foreground
./scripts/assistant/Stop.ps1
```

Файли в `.local/assistant` на диску проєкту (на цьому ПК — E), поза Git. Встановлення займає приблизно 4,47 GB разом із CUDA/CPU runtime й архівами; сам GGUF — 2 497 281 120 байтів. Default для цього ПК: NVIDIA CUDA0, повне GPU-вивантаження, Q4_K_M ваги, Q8_0 KV, контекст 2048 токенів, один slot, до 4 CPU-потоків. Це локальні налаштування ноутбука з 32 GB RAM/RTX 3050 Ti 4 GB; на іншому комп’ютері треба перевірити пристрої/пам’ять або скористатися `-Cpu`. Запуск ручний; автозапуск із Windows не додається.

Разом мають працювати PostgreSQL, API на 5080, frontend на 4200 та runtime на 4310. Модель не входить до Git: після clone чат потребує окремого Setup/Start; інші розділи не залежать від runtime. На цьому ПК фактичні відповіді моделі займали приблизно 60–100 секунд; це спостереження smoke test, не гарантія швидкості. Навчання чи fine-tuning Qwen не виконувалися. Для публічного розгортання потрібен окремий контрольований inference-хост, ліміти й перевірка навантаження; localhost користувача відвідувачу сайту недоступний.

## Перевірки

Додано backend-тести валідації, відкидання невідомих source IDs і відсутності перенесення історії між викликами; frontend-тести контексту, очищення/скасування, виходу/pagehide, обмеження історії, помилок і безпечних посилань. Є компонентна axe-перевірка (без вимірювання контрасту в jsdom). Реальний наскрізний smoke test повернув сім титулів Гамільтона з посиланням на кар’єрний зріз. Це не повна оцінка фактичної точності чи prompt-injection robustness.
