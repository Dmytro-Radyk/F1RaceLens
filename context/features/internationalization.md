# Багатомовний інтерфейс

## Поведінка

Angular-застосунок підтримує українську (`uk`, початкова), англійську (`en`), німецьку (`de`), італійську (`it`), іспанську (`es`) та французьку (`fr`). Мови позначені власними назвами, без прапорців країн. Перемикач є у верхній панелі застосунку та на сторінці входу/реєстрації.

Вибір зберігається у `localStorage` як `f1-race-lens-language`. Невідоме значення повертає українську. Якщо сховище заблоковане, перемикання працює в пам’яті. Збережена мова відновлюється до початкового рендерингу; URL, сезон, фільтри, дані та поля форм не скидаються. Оновлюються `html.lang` і заголовок вкладки.

Каталог завантажується з власних статичних файлів лише за потреби; українська використовує вихідні повідомлення. При помилці завантаження зберігається поточна мова й показується повідомлення для повторної спроби. За швидкого вибору кількох мов перемагає останній запит. Перемикання не повторює API-запити даних.

Перекладені навігація, авторизація, головна, календар/сесії/результати, заліки, пілоти, команди, порівняння, аналітика, статистичні прогнози, помилки, застарілі стани, підказки графіків та доступні назви. Дати й числа використовують `Intl` з локаллю вибраної мови; часовий пояс залишається користувацьким. Пороги часток симуляцій зберігають свою семантику (`<0.1%` англійською, `<0,1%` німецькою).

Власні назви пілотів, команд, трас і Гран-прі та довідкові поля національності зберігаються як у Jolpica. Сирі причини сходів у таблицях залишаються мовою джерела, як указано в поясненні таблиці; відомі статуси в підказках локалізовані. Окремий технічний ML-переглядач на 4300 не входить до цієї реалізації.

## Підтримка перекладів

Код: `frontend/src/app/core/i18n/`. Каталоги `catalogs/en.ts`, `de.ts`, `it.ts`, `es.ts`, `fr.ts` містять однакові ключі — українські вихідні повідомлення. Параметри `{0}`, `{1}` дозволяють змінювати порядок речень без склеювання перекладених слів. `TranslatePipe` реагує на мову; адаптер параметризованих повідомлень також підтримує наявні підписи графіків. Форматувальні функції читають `currentLocale()`, а не фіксовану `uk-UA`.

Нові тексти додавати через `translate` та одночасно до всіх п’яти каталогів. Не перекладати стабільні ідентифікатори маршрутів, API, CSS-класи, назви джерел або вхідні дані користувача. Не використовувати HTML у перекладах: Angular екранує текст. Українські повідомлення станів прогнозу, отримані з API, мають відповідні ключі; при зміні їхнього тексту перевірити каталоги.

З `frontend`:

```powershell
npm run check:i18n
npm run build
npm test -- --watch=false
```

Перевірка каталогів контролює наявність усіх вихідних повідомлень, відсутність неперекладеного статичного тексту шаблонів, однакові ключі, дублікати й параметри. Тести перевіряють збереження/відновлення, недоступне сховище/каталог, швидкі зміни, форматування, підказки та перемикання живої сторінки без зміни року, фільтра, URL чи повторного запиту.

## Перевірка реалізації 19.10.2026

625 вихідних повідомлень та п’ять повних перекладених каталогів пройшли `check:i18n`. 105 frontend-тестів успішні, production-збірка без попереджень; початковий пакет близько 300 кБ, переклади завантажуються окремо. У живому браузері перевірено всі шість мов на головній та прогнозах, ширину 320 px без горизонтального переповнення сторінки, мобільне меню, світлу/темну тему, форму з локалізованою помилкою та збереженим полем, усі розділи англійською й підказку графіка. Структурні перевірки каталогів не є заміною редакторської перевірки носіями мов. Початковий етап локалізації не змінював backend і ML; наступна інтеграція прогнозів описана окремо в integrated-forecasts.md.
